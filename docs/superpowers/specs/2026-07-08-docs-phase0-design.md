# Phase 0 Documentation Design — terraform-provider-mixpanel

**Date:** 2026-07-08
**Status:** Approved (design presented and accepted in session)
**Scope decisions (user-confirmed):** narrative as guide + distilled front doors · honest trust recalibration · full 89-page reference sweep · markdown plus adjacent-correctness files (guide example `.tf`s, Makefile guard, template sync); no Go code changes.

## 1. Purpose

Crystallize and extend the committed markdown in `docs/` so it (a) communicates the value, novelty, and competitive position of infrastructure-as-code for product analytics to the broader Mixpanel org — including readers with no Terraform background — and (b) lets practitioners use the provider correctly and effectively. The committed markdown is the canonical corpus; later publishing surfaces (GH Pages, wiki, Notion) derive from it and are out of scope for this phase.

## 2. Ground truths this design relies on

- `docs/` is **hand-curated**. `make docs` (`go generate ./...`) is a no-op: no `//go:generate` directives, no tfplugindocs in `go.mod`, no docs step in CI. `gen/README.md` step 6 mandates hand-editing. The `<!-- schema generated by tfplugindocs -->` markers are historical seeding. Running `tfplugindocs generate` manually would destroy hand-written content (only `templates/index.md.tmpl` exists as a template) — Phase 0 adds a guard against this (§9).
- The registry renders `index.md`, `guides/`, `resources/`, `data-sources/`; other paths under `docs/` (including `docs/superpowers/`) are ignored by the registry but render on GitHub.
- Provider registers **43 resources**, **33 singular data sources**, **13 plural/list data sources** (`internal/provider/registry.go`). 15 registered types lack doc pages: resources `business_context`, `service_account_project`; all 13 plural/list data sources (incl. `schema_graph`).
- Verified schema facts that correct existing docs: `mixpanel_dashboard` has `title` (no `name`, no `metadata`); `mixpanel_custom_property` has no `data_type`; the custom-property data source looks up by `custom_property_id` only (no by-name lookup exists); `mixpanel_cohort`'s JSON blob is `groups` (`selector` is a typed nested attribute, not a JSON string); `mixpanel_data_group` uses `display_name` + `property_name`.
- Market position (verified 2026-07-08): PostHog ships the only comparable official provider (18 resources, incl. dashboards/insights); Amplitude and Heap have nothing first-party. Claims in docs must be the defensible "breadth + depth of the analytical surface" form, never "first/only."

## 4. The two new guides

### 4.1 `docs/guides/analytics-as-code.md`

Audience: a smart product/analytics person first, credible to an infra engineer. Outline (each numbered item is a section):

1. **The problem** — analytics config is load-bearing but lives as unversioned click-state: "who changed this metric and why?", dev/staging/prod divergence, taxonomy decay, tribal-memory dashboards.
2. **The move** — define it as code. One short, real, schema-verified HCL block (cohort + metric + lexicon tag) and the plan → review → apply loop explained in plain English.
3. **What you get** — PR review and `git blame` for analytics definitions; environment parity; drift detection (webapp edits become visible diffs); scale via `for_each`; governance as code; disaster recovery / project bootstrap.
4. **The agentic multiplier** — AI leverage is highest on code; expressing the analytics estate as code moves it into that medium. `terraform plan` + PR review is the native safety harness for agent-proposed change: agents read the whole estate, propose diffs, humans approve, state converges. One concrete scenario (launch-week analytics stood up as a reviewable PR). No hype vocabulary; the argument stands on the mechanics.
5. **Honest scoping** — exploratory/ad-hoc analysis stays in the UI; durable shared artifacts belong in code; import + drift detection make the two coexist.
6. **Where this stands** — factual comparison: PostHog official provider 18 resources; Amplitude/Heap none first-party; this provider 43 resources + 46 data sources across analytical, governance, and admin surfaces, with engineering depth (plan-time validation, drift semantics, bulk import) detailed elsewhere. Dated claim, phrased to survive scrutiny.
7. **Pointers** — getting-started, import ("adopt what you already have"), portability, drift detection.

### 4.2 `docs/guides/getting-started.md`

Audience: never touched Terraform. Steps: prerequisites (service account with roles/permissions note, project id, Terraform or OpenTofu install) → **"Terraform in five concepts"** (configuration, state, plan, apply, drift — one analytics-flavored paragraph each; this replaces a separate glossary doc) → first config (provider block + `mixpanel_annotation`, the safest visible object) → `terraform plan` and how to read a diff → `apply` → see it in the Mixpanel UI → change it, re-plan (the loop) → something real (cohort with a valid minimal `groups` payload) → cleanup/destroy → next steps (import existing objects; portability; sharing semantics for service-account-created entities — link, since "I applied but see nothing in the UI" is the #1 predictable newcomer trap) → short "running this with an AI agent" callout mapping the same steps to prompts.

Every example schema-verified per §10.

## 8. Terminology & style rules (to be encoded in CONTRIBUTING.md)

- Mixpanel product vocabulary leads; Terraform type follows: "a Mixpanel **Board** (`mixpanel_dashboard`)". Board/dashboard equivalence defined in index.md and on the dashboard + bookmark pages; elsewhere use "board" for the product object.
- `mixpanel_tag` (data source) ↔ `mixpanel_lexicon_tag` (resource): cross-reference on both pages; explain they address the same object.
- Bookmarks are called "saved reports (bookmarks)" on first mention per page, "report" thereafter.
- Plain-English-first: every page's intro must be readable by a non-Terraform PM; HTTP/API/wire vocabulary is allowed in guidance sections but never in the intro sentence. Terraform jargon (taint, ForceNew, Optional+Computed) gets a parenthetical gloss on first use per page.
- Alpha/trust language lives only in index.md (§5.1).
- Cross-links are real markdown links (relative within `docs/`), not prose mentions. Links must not escape `docs/` except as absolute GitHub URLs.
- Internal codenames (GREEN-*, ARB, spec 045/047, "frozen spec", pipeline artifact names) never appear in `docs/`.

## 10. Example-verification protocol (docs as code)

1. Every HCL example is checked attribute-by-attribute against the generated schema (`internal/provider/resource_<entity>/*_gen.go`, `datasource_<entity>/*_gen.go`) plus hand-injected attributes (`<entity>_resource.go`) and `<entity>_spec.go`.
2. Where tooling allows, examples are also mechanically validated: build the provider, point a scratch Terraform/OpenTofu working dir at it via `dev_overrides`, run `terraform validate` (validates schemas without credentials). If no TF/OpenTofu binary is available in the environment, step 1 alone gates, and the follow-ups list carries a CI validation job.
3. JSON blob payloads in examples (cohort `groups`, metric/behavior `definition`, bookmark `params`) must satisfy the plan-time validation rules documented on their resource pages.
4. No example ships unverified. New pages state nothing about API behavior that isn't sourced from code, existing verified docs, or internal docs (ACCEPTANCE_TESTING.md, gen/README.md).

## 13. Acceptance criteria

- No HCL example anywhere in `docs/` or `examples/guides/` references a non-existent attribute (protocol §10 applied; spot-audit clean).

- `grep -rnE "GREEN-1[02]|\bARB\b|api-spec\.yml|extra=\"allow\"" docs/` and `grep -rniE "FE editor|frozen spec|production-tested" docs/` both return nothing (`\bARB\b` case-sensitive to avoid matching "arbitrary").
- `docs/index.md` lists all guides; every guide has complete frontmatter; capability map covers all seven families; maturity table present and consistent with `*_acc_test.go` reality.
- All relative links in `docs/` resolve; none escapes `docs/` non-absolutely.
- `templates/index.md.tmpl` and `docs/index.md` bodies match.
- History is wave-scoped commits on `docs-phase-0`.
